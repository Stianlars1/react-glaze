Playground ↗Edge smoothing: before/after ↗

Optical glass for the web.

One configurable React component, with an automatically captured background and normal HTML content. These notes describe the current alpha and the browser experiments behind it. Observations are from September 6–7, 2026.

One component, different uses.

Use LiquidGlass as a button, link, div or another supported element. Pass standard HTML events and attributes alongside the glass settings. The button and card examples in the playground use the same component.

<LiquidGlass as="button" width={240} height={64}
  radius={32} onClick={handleClick}>
  Explore the glass
</LiquidGlass>

The background is ordinary page HTML. You do not pass a background image to the component. The alpha selects the nearest ancestor with an opaque background color, or the document body, and takes snapshots for the optical renderer.

contentMode="sharp" keeps native content above the glass. contentMode="refracted" also includes the content in the snapshot. Refracted text and controls are experimental: hit areas, selection and carets still follow the original DOM layout.

What the reference demonstrates.

The Drawn To Optical Type scene supplies the original material, lighting and smooth lens. Its visible typography is painted into a canvas texture. It demonstrates the optical effect; automatic capture of arbitrary page content is a separate problem.

The alpha retains the reference material values and adds a rounded surface. Its initial bevel produced stepped refraction, which was corrected by sharing normals between adjacent faces. Compare the edge before and after the fix.

Rendering approaches explored.

ApproachWhat the experiments showed
DOM snapshots + Three.jsThe current alpha captures ordinary HTML and renders optical glass with one shared WebGL renderer. Each surface uses its own canvas layer to preserve native DOM stacking. Complex content can be omitted or reconstructed incorrectly.
Native HTML-in-CanvasA Chrome experiment connected real HTML to the reference material. The source had to belong to the canvas, and the tested API required an experimental flag. This did not establish automatic capture of arbitrary surrounding DOM.
HTML-in-Canvas polyfillA locally adapted three-html-render 0.1.2 integration worked for basic text examples. It still relied on DOM reconstruction and had content and version constraints.
CSS/SVG backdrop filtersThe displacement test worked in Chrome. The tested Safari and Firefox paths did not provide the same result. These experiments did not establish a common full-effect implementation.
WebGPU / VGPUVGPU 0.4.0 initialized and accepted canvas uploads in the test engines. It did not provide general access to the page’s pixels. No comparative glass benchmark established a performance advantage over Three.js.
Screen captureRequires a user-selected capture source and permission. It does not fit a transparent dependency inside an ordinary reusable component.

Current validation.

The playground was checked in Chrome 152, Firefox 155’s test build, WebKit 26.5’s test engine and Safari 26.4 on Mac. Test builds are not a certification of every released browser. Checks included background changes, native clicks, dragging, glass on/off, responsive layouts and selected content modes.

The React package also built and ran in a separate Next.js 16.3.4 app installed from a local tarball. That fixture exercised two surfaces, source changes, unmounting and remounting. The package name is provisional and the package is not yet published to npm.

Idle, hidden, offscreen and disabled surfaces pause scheduled work. Moving sharp glass over an unchanged background reuses the existing snapshot. Updating the background itself requires another asynchronous capture.

Safari needed a 120 ms settling interval before redrawing SVG snapshots with embedded images. This fixed the observed missing-image cases, but adds latency to animated backgrounds. It is a bounded workaround, not a general browser support guarantee.

Known limits and next checks.

  • Cross-origin images without suitable CORS access, foreign iframes, video, canvas and closed shadow roots may be unavailable or incomplete.
  • Nested scrolling, complex filters, masks, blending, sticky/fixed layouts and transformed ancestors need further validation.
  • Sibling glass surfaces are not recursively refracted. The backdrop root is chosen at mount.
  • Continuous background capture can lag behind animation. This alpha does not promise 60 fps or seamless WebGL context restoration.
  • Physical iPhone, iPad and Android devices, plus Windows Edge, have not been verified. A mobile viewport or touch emulation does not replace device testing.

The next work is to validate these cases against visible pixel evidence, improve capture scheduling and source fidelity, and define the supported release contract before promising broad production support.
